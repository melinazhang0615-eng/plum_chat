# Fibre Chat MVP 产品需求文档

> 版本：v0.3
> 状态：本地联合开发基线
> 日期：2026-08-06
> 参考产品：[Tipsy Chat](https://tipsy.chat/)

> 范围决策：首版聊天使用同步 JSON 响应，不做 SSE/逐 token 流式展示；流式能力作为后续增强，不影响本期验收。

## 1. 产品概述

Fibre Chat 是一款以虚拟角色为核心的 AI 沉浸式对话产品。用户在角色 Feed 中发现感兴趣的角色，进入角色专属聊天场景，与角色进行连续的文字对话，并可按偏好切换不同 AI 模型。

MVP 目标是验证最短核心链路：

**发现角色 → 进入故事 → 连续聊天 → 切换模型 → 消耗模拟金币 → 下次继续聊天**

本产品参考 Tipsy Chat 的核心产品结构和交互思路，但不直接复制其品牌、文案、角色内容或受版权保护的视觉资产。

## 2. 产品目标

### 2.1 MVP 目标

- 用户可以通过一个主 Feed 浏览角色。
- 用户可以进入任一角色的聊天场景并收发纯文字消息。
- AI 能遵循角色设定，保持相对稳定的角色口吻和故事背景。
- 用户可以在聊天中切换模型，切换后从下一条消息生效。
- 系统提供模拟金币余额，新用户默认获得 1000 金币。
- 聊天成功生成回复后扣除对应模型的金币，形成完整但不涉及真实支付的消费闭环。
- 系统内置 2 个调试角色，后续可替换或批量导入正式角色资产。

### 2.2 成功判断

MVP 上线后重点观察：

- Feed 角色卡点击率。
- 进入聊天后的首条消息发送率。
- 单次会话平均用户消息数。
- 次日再次打开并继续聊天的用户比例。
- 不同模型的选择比例、生成成功率和响应时长。

第一版不设置硬性业务目标，先保证核心链路可用并建立基础埋点。

## 3. 目标用户与使用场景

### 3.1 目标用户

- 喜欢互动故事、角色扮演、虚拟陪伴或网文式剧情体验的用户。
- 希望与设定明确、性格稳定的 AI 角色持续对话的用户。
- 愿意通过不同模型在速度、质量和消耗之间做选择的用户。

### 3.2 典型场景

1. 用户打开网站，从 Feed 中浏览不同类型的角色。
2. 用户被角色封面、标题或故事钩子吸引，点击进入聊天。
3. 系统展示角色设定摘要和开场白，用户直接回复并推动剧情。
4. 用户觉得当前模型回复不够细腻，切换到更高质量模型继续聊天。
5. 用户离开后再次进入同一角色，系统恢复上次会话和所选模型。

## 4. MVP 范围

### 4.1 本期包含

| 模块 | MVP 能力 |
| --- | --- |
| 用户 | 使用一条预置测试账号；跳过注册与登录；账号初始化 1000 金币 |
| 主 Feed | 展示一个固定 Feed；支持角色卡列表及基础加载状态 |
| 角色 | 内置 2 个角色；展示封面、头像、名称、标签、简介和热度模拟值 |
| 聊天 | 角色开场白、纯文字收发、同步完整回复、历史消息恢复、生成中/失败状态 |
| 模型 | 提供 3 个模型档位；聊天内切换；下一条用户消息起生效 |
| 金币 | 展示余额；按成功回复扣费；不接入充值、支付和订阅 |
| 数据 | 保存测试账号、余额、会话、消息、当前模型和角色数据 |
| 基础运营 | 角色支持启用/停用及 Feed 排序配置，可先通过配置文件或数据库完成 |

### 4.2 本期不包含

- 图片消息、图片生成、语音输入、语音回复、视频能力。
- 真实充值、订阅、支付、提现、优惠券或任何付费权益。
- 多 Feed、推荐算法、Trending、Following、Worlds 等频道。
- 搜索、筛选、收藏、关注、点赞、评论、分享。
- 用户自行创建或编辑角色。
- 创作者主页、创作者激励、活动 Banner 和任务系统。
- 群聊、多角色同场对话。
- 用户自定义 Persona、记忆编辑、知识库或长期记忆管理界面。
- 消息编辑、分支剧情、重新生成、多候选回复、置顶消息。
- 完整运营后台；MVP 可通过种子数据或简单配置维护角色。
- 原生 iOS/Android 客户端；第一版默认采用响应式 Web。

## 5. 信息架构

```text
主 Feed /
├── 顶部栏
│   ├── 产品标识
│   └── 金币余额
├── 角色卡列表
└── 角色卡 → 聊天页 /chat/:characterId
    ├── 角色信息区
    ├── 消息区
    ├── 模型选择器
    └── 文字输入区
```

MVP 只保留两个主要页面：主 Feed 和聊天页。角色的详情信息可在进入聊天前以聊天页顶部卡片或首屏简介呈现，不单独增加详情页。

## 6. 核心用户流程

### 6.1 首次访问

1. 用户打开产品。
2. 系统读取预置 Fibre 测试账号；不存在时提示开发环境尚未初始化。
3. 系统展示主 Feed。
4. 顶部栏显示当前金币余额。

测试账号通过幂等 seed 初始化 1000 金币。再次打开时不重复赠送，直接恢复该账号已有余额和聊天记录。

### 6.2 开始聊天

1. 用户点击角色卡。
2. 系统进入对应聊天页。
3. 若该角色无历史会话，创建新会话并展示角色开场白；开场白不扣金币。
4. 若已有会话，恢复历史消息、当前模型和阅读位置。
5. 用户输入文字并发送。
6. 系统校验余额，记录用户消息，并请求模型生成角色回复。
7. 请求期间展示“角色正在回复”，成功后一次性展示完整回复。
8. 回复成功后记录完整消息并扣除金币。

### 6.3 切换模型

1. 用户点击当前模型名称。
2. 系统展示可选模型名称、简短定位和单次预计消耗。
3. 用户选择模型。
4. 页面即时展示新的当前模型。
5. 新模型从下一条用户消息开始生效，不重新生成已有消息。

## 7. 功能需求

### 7.1 测试账号与状态恢复

#### FR-U-01 预置测试账号

- MVP 不实现注册、登录或匿名身份创建。
- 开发 seed 直接在平台用户表中创建一条固定 Fibre 测试账号，并创建 Fibre membership、入口 account 和钱包。
- Fibre API 在 `local/test` 环境固定解析为该测试账号；生产环境必须 fail closed。

#### FR-U-02 状态恢复

- 所有本地客户端共享该测试账号的余额、会话和消息记录。
- 刷新页面或重启前后端后，从服务端数据库恢复状态。
- 正式账号体系与多用户隔离留到后续版本。

### 7.2 主 Feed

#### FR-F-01 Feed 展示

- 页面默认展示所有已启用角色。
- MVP 使用固定排序字段，不做个性化推荐。
- 桌面端建议为多列卡片布局，移动端为单列或双列布局。

#### FR-F-02 角色卡信息

每张卡至少展示：

- 角色封面或占位视觉。
- 角色头像。
- 角色名称。
- 一句话故事钩子。
- 2–4 个标签。
- 模拟热度值。

点击卡片任意主要区域进入该角色聊天页。

#### FR-F-03 Feed 状态

- 加载中：展示骨架屏。
- 空状态：展示“暂时没有可用角色”。
- 加载失败：展示错误提示和重试按钮。

### 7.3 聊天场景

#### FR-C-01 首次进入

- 展示角色头像、名称、简介或故事钩子。
- 新会话自动插入一条角色开场白。
- 明确提示内容由 AI 生成。

#### FR-C-02 文字消息

- 仅支持纯文本输入。
- Enter 发送，Shift + Enter 换行；移动端点击发送按钮发送。
- 空消息不可发送。
- MVP 建议单条用户消息最大 2000 字符，超限时明确提示。
- 发送后用户消息立即出现在消息区。

#### FR-C-03 AI 回复

- 首版使用同步完整输出；SSE 流式输出留到后续版本。
- 生成期间禁用重复发送，显示“角色正在回复”。
- 请求成功后保存最终回复及本次使用的模型。
- 请求失败时保留用户消息，展示失败状态和“重试”入口。
- 失败、超时或被用户取消的请求不扣金币。

#### FR-C-04 上下文与角色一致性

模型请求至少包含：

- 角色系统设定。
- 角色开场背景。
- 当前会话内最近若干条消息。
- 基础安全约束。

MVP 可采用固定上下文窗口或按 token 截断；被截断的旧消息仍保存在产品侧历史记录中。

#### FR-C-05 历史记录

- 测试账号与同一角色默认只维护一个连续会话。
- 重新进入角色时恢复历史消息。
- 消息按时间正序展示，默认滚动至最近一条。
- MVP 提供“重新开始”入口：二次确认后归档原会话并创建新会话，余额不重置。

### 7.4 模型切换

#### FR-M-01 模型列表

MVP 提供 3 个产品化模型档位，实际供应商模型通过服务端配置映射，前端不硬编码供应商名称。

| 展示名称（暂定） | 用户感知 | 单次成功回复消耗 |
| --- | --- | ---: |
| 极速 | 速度优先，适合快速对话 | 1 金币 |
| 均衡 | 质量与速度平衡，默认模型 | 3 金币 |
| 沉浸 | 描写和角色扮演能力优先 | 5 金币 |

- 默认选择“均衡”。
- 每个模型显示名称、简短说明和预计金币消耗。
- 模型可由服务端启用、停用或更换实际模型映射。

#### FR-M-02 切换规则

- 用户可在发送消息前随时切换模型。
- 切换只影响后续生成，不影响已有消息。
- 请求生成期间不可切换，或切换只在当前生成完成后生效；MVP 推荐直接禁用切换控件。
- 当前选中模型按会话保存。

### 7.5 模拟金币

#### FR-G-01 初始化

- 预置测试账号在 seed 首次执行时获得 1000 金币。
- seed 与赠送操作需具备幂等性，刷新页面或重复执行脚本不得重复赠送。

#### FR-G-02 展示

- 主 Feed 顶部和聊天页顶部均展示当前余额。
- AI 回复成功后余额即时刷新。

#### FR-G-03 扣费

- 扣费金额由本次请求实际使用的模型决定。
- 只有 AI 回复成功完成并写入消息后才扣费。
- 同一生成请求重复回调或重试不得重复扣费。
- 金币账变需记录原因、关联会话、关联消息、变动值和变动后余额。

#### FR-G-04 余额不足

- 发送前若余额小于当前模型费用，禁止发送并提示“金币不足，请切换到更低消耗的模型”。
- 本期没有充值入口，不展示虚假的支付按钮。
- 为方便测试，可在开发环境提供重置金币的脚本或管理接口，不在正式用户界面暴露。

## 8. 页面需求

### 8.1 主 Feed 页面

#### 页面组成

- 顶部栏：产品 Logo/名称、金币图标和余额。
- 标题区：简短欢迎语，例如“选择一个故事，开始聊天”。
- 角色卡网格：展示全部启用角色。

#### 关键交互

- 点击角色卡进入聊天。
- 返回 Feed 后保留原滚动位置，属于建议项，不阻塞 MVP 发布。

### 8.2 聊天页面

#### 页面组成

- 顶部栏：返回、角色头像与名称、金币余额、重新开始入口。
- 角色简介区：首次进入时展示，可折叠。
- 消息区：角色开场白、用户消息、AI 消息、生成状态和失败状态。
- 输入区：模型选择器、文本框、发送按钮。

#### 响应式要求

- 桌面端聊天主体居中，保持适合阅读的最大宽度。
- 移动端输入区固定在可视区域底部，不被软键盘永久遮挡。
- 长消息应正确换行，不出现横向溢出。

## 11. AI 生成要求

- 服务端负责拼装提示词，角色私有设定不得下发到前端。
- 不同模型档位共享同一角色设定和会话上下文格式。
- AI 回复默认使用角色所处语言；用户切换语言时应自然跟随。
- 回复应保持角色身份，不主动声称自己是语言模型。
- 不把前端展示的金币、模型选择等产品元信息写入角色对话内容。
- 服务端设置生成超时，并记录模型、耗时、token 用量、错误类型和请求 ID。
- 第一版需接入基础内容安全策略；具体分级、年龄限制和敏感内容边界需在开发前单独确认。

## 12. 非功能需求

### 12.1 性能

- Feed 首屏在正常网络下应尽快展示骨架屏，并在 2 秒左右展示本地/服务端角色数据。
- 用户发送后 1 秒内应出现明确的生成中反馈。
- 模型首字延迟和完整生成耗时需埋点记录，不以固定数值阻塞 MVP。

### 12.2 稳定性

- 消息保存、AI 生成和金币扣费需可追踪。
- 页面刷新不得重复创建开场白或重复扣费。
- 同步请求失败或超时时明确标记失败，不保存不完整回复，也不扣金币。

### 12.3 安全与隐私

- 不在前端暴露模型供应商密钥、角色系统提示词和后台配置。
- 用户输入视为不可信内容，服务端需做长度限制和必要的安全校验。
- 日志避免记录完整敏感对话；如需调试，应支持脱敏和访问控制。
- 页面展示“AI 生成内容”提示。

### 12.4 兼容性

- 支持当前主流桌面端 Chrome、Safari。
- 支持主流移动端浏览器的响应式布局。

## 14. MVP 验收标准

### 14.1 主 Feed

- 新用户打开页面后可看到 2 张调试角色卡。
- 顶部正确显示 1000 金币。
- 点击任一角色卡可进入对应聊天页。

### 14.2 聊天

- 首次进入可看到正确的角色开场白，且不扣金币。
- 用户可发送纯文字消息；等待期间看到生成中状态，成功后看到完整 AI 回复。
- AI 回复能基本遵循所选角色的身份、语气和场景。
- 刷新页面或退出再进入后，历史消息仍存在。
- 请求失败时可重试，失败请求不扣金币。
- 不存在图片、语音或视频发送入口。

### 14.3 模型与金币

- 用户可看到 3 个模型档位及对应金币消耗。
- 切换模型后，下一条生成使用新模型。
- 成功回复后按对应档位扣除 1、3 或 5 金币。
- 页面余额与账变流水一致。
- 刷新页面不会重复获得 1000 金币或重复扣费。
- 余额不足时无法发送，并提示切换低消耗模型。

## 15. 迭代建议

### Phase 1：核心闭环

- 预置测试账号与 1000 初始金币。
- 固定角色 Feed。
- 2 个调试角色。
- 单角色连续文字聊天。
- 3 档模型切换与固定金币扣费。
- 会话持久化与基础埋点。

### Phase 1.1：体验完善

- 消息重新生成、复制和删除。
- 角色搜索与标签筛选。
- 收藏角色和最近聊天。
- 正式角色资产批量导入工具。
- 正式账号登录及跨设备同步。

### Phase 2：内容与增长

- 多 Feed 与推荐排序。
- 用户 Persona 和长期记忆。
- 角色创建工具与创作者体系。
- 图片、语音等多模态能力。
- 在验证留存与消费意愿后，再评估真实付费体系。

## 16. 待确认事项

以下问题不阻塞 MVP 原型，但应在进入开发前确认：

1. 第一版是否明确只做 Web，还是需要同时考虑移动端壳应用。
2. 实际接入哪些模型供应商，以及 3 个产品档位分别映射到什么模型。
3. 内容安全尺度、目标用户年龄范围，以及是否允许成人向角色内容。
4. 从本地 MVP 进入多人测试或公开部署前，选择手机号、邮箱、第三方登录或匿名设备身份方案。
5. 正式角色资产的字段格式、图片比例和批量导入方式。
6. 是否需要在 MVP 中提供会话列表；本稿默认通过 Feed 再次进入角色来恢复会话。
