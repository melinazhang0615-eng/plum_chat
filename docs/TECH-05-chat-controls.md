# TECH-05 聊天页控件语义与实现边界

## 1. 目的

记录聊天窗顶部与输入区控件的产品语义，避免后续只复刻图标而没有真实功能，也作为前后端补齐角色卡、记忆和多媒体能力时的接口依据。

## 2. 控件对照

| 区域 | 控件 | 产品含义 | MVP 状态 |
| --- | --- | --- | --- |
| 聊天窗顶部 | 角色头像 | 当前对话对象；点击恢复显示左侧 Profile | 已实现，纯前端布局状态 |
| 聊天窗顶部 | Lv0 | 当前用户与角色的关系成长等级 | MVP 固定为 Lv0；后续由关系成长系统计算 |
| 聊天窗顶部 | 书本 + 数字 | 当前故事章节与章节入口 | MVP 展示第 1 章；章节系统尚未接入 |
| 聊天窗顶部 | 静音 + Auto | 自动朗读 AI 回复 | 首版不支持语音，禁用并明确标注 coming soon |
| 聊天窗顶部 | 点赞 + 数字 | 用户对角色的点赞状态及计数 | MVP 前端模拟切换；尚未持久化 |
| 聊天窗顶部 | 爱心 + 数字 | 用户收藏 / 喜爱该角色的状态及计数 | MVP 前端模拟切换；尚未持久化 |
| 聊天窗顶部 | 三点圆形按钮 | 布局与对话设置入口 | 已实现；包含恢复默认布局、重新开始对话 |
| 输入区上方左侧 | 六边形双箭头 | 对话模型 / 模式选择 | 已实现，直接调用现有模型切换接口 |
| 输入区上方左侧 | Role Card | 用户在当前故事里的身份、称呼和背景 | MVP 展示测试用户；尚未注入模型上下文 |
| 输入区上方左侧 | Pinned | 用户主动置顶、需要长期记住的事实或剧情节点 | MVP 空状态；尚未注入模型上下文 |
| 输入区上方右侧 | 图片 + 闪光 | 根据当前剧情生成场景图片 | 首版范围外，禁用并明确标注 coming soon |
| 输入区上方右侧 | 视频 + 闪光 | 根据当前剧情生成短视频 | 首版范围外，禁用并明确标注 coming soon |
| 输入区上方右侧 | 叠层图片 | 打开本对话生成的媒体图库 | 首版范围外，禁用并明确标注 coming soon |
| 输入框左侧 | 灯泡 | 生成下一步剧情灵感 / 建议回复 | 已实现为本地可编辑提示词，不触发扣费 |
| 输入框右侧 | 纸飞机 | 发送文本消息 | 已实现，调用 Human-AI 对话链路并按模型扣金币 |
| 消息区右下角 | 向下箭头 | 用户离开底部时回到最新消息 | 已实现，纯前端滚动状态 |

## 3. 后端扩展建议

### 3.1 Role Card

属于 Fibre 业务域，不应直接塞进共享 Human-AI Runtime 的业务表。建议新增：

- `fibre_user_personas`：用户可复用身份卡；
- `fibre_conversation_personas`：某段对话选中的身份卡及必要快照；
- 对话请求进入 Runtime 前，由 Fibre 应用服务将生效的身份卡编译成受控上下文。

首版测试账号可有一张默认身份卡，但正式数据必须归属用户，支持显式选择和取消。

### 3.2 Pinned Memory

建议新增 `fibre_conversation_pins`，至少包含：

- Fibre conversation ID；
- 来源消息或公开 Memory ID（可为空）；
- 用户确认过的文本快照；
- 排序、启用状态和创建时间。

Pinned 是用户主动维护的私人对话上下文，不等同于 Profile 页的公开 Memory，也不应直接引用 Runtime Session ID。发送消息前由 Fibre 应用服务聚合，再交给共享 Runtime。

### 3.3 多媒体

图片、视频和图库不属于当前文本聊天 MVP。未来接入时应作为 Fibre 的异步媒体任务与资产域实现，只复用鉴权、任务队列、对象存储等业务无关技术模块，不把它们耦合进核心文本对话表。

## 4. 交互原则

- 有真实能力的按钮必须调用真实链路，模型选择不能只是视觉状态。
- 未实现能力使用禁用态和明确说明，不展示可点击的假入口。
- Inspiration 生成的内容只填入输入框，由用户确认后才发送和扣费。
- Profile、Role Card、Pinned Memory 是三个不同概念：角色公开资料、用户故事身份、当前私聊长期事实，数据模型不得混用。
