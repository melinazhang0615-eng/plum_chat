## 已确认决策

### 顶部导航与品牌区

- 已确认：删除“云端图标 + 更多（三点）”组合按钮。
- 已确认：删除“Download”按钮。
- 说明：删除整个可见控件及其占位，不保留空白区域。
- 已确认：点击“搜索”后，在当前页面展开强化搜索框，并带有热搜词下拉区域。
- 已确认：点击“Create”跳转到角色创建页。
- 已确认：点击地球仪后展开语言切换列表。
- 已确认：顶部登录后的用户名称可点击，点击后展开用户设置下拉菜单。
- 待后续填充：搜索范围与结果页、热搜词内容和来源、语言列表、角色创建页字段、用户设置菜单项。
- 顶部 Action 采用“图标优先”策略，避免桌面空间不足和多语言文案导致按钮宽度不稳定。
- 搜索和 Create 使用纯图标按钮；语言使用独立的语言切换图标；金币使用图标 + 数字；用户入口使用头像 + 可截断名称 + 下拉箭头。
- 中等宽度下用户入口可收缩为头像 + 下拉箭头；移动端只保留核心图标，次要入口可收进菜单。
- 已确认：纯图标按钮不使用悬停 Tooltip；仍保留不可见的无障碍名称。
- 已确认：语言入口不使用地球仪，改用“文/A”类型的翻译图标。

### 分类导航

- 已确认保留内容分类：`For You`、`Trending`、`Latest`、`Popular`、`Following`。
- 已确认保留 `Limitless` 开关；它独立于主内容分类，可叠加到当前分类。
- 已确认删除 `Worlds`。
- 已确认保留角色性别选项；它独立于主内容分类，可叠加到当前分类。具体性别选项、文案和筛选逻辑待后续填充。
- `For You`、`Trending`、`Latest`、`Popular`、`Following` 是主内容分类，彼此互斥，任一时刻选中一个。
- 已确认保留筛选器。
- 筛选器点击后展开标签列表，用户可用标签筛选角色内容。
- 筛选标签的具体内容、数据来源、创建和生产流程后续实现；当前阶段只定义交互入口和展示容器。
- `Limitless` 进入首页时默认关闭。
- 角色性别筛选的初始值来自新用户路径中的性别选择；待 onboarding 需求确定后再打通数据和逻辑。
- 旧用户或缺少性别选择数据时的默认值，留待 onboarding 需求讨论时确认。
- 移动端分类区使用两行结构，不隐藏桌面端已有筛选能力。
- 移动端第一行是可横向滑动的主分类：`For You`、`Trending`、`Latest`、`Popular`、`Following`。
- 移动端第二行固定显示附加筛选：`Limitless`、角色性别、标签筛选器。
- 已确认不调转两行顺序：先选择主内容分类，再设置附加筛选。
- 当前选中的主分类应自动保持在横向可见区域；标签筛选面板优先使用移动端底部 Sheet。

#### 重要 TODO：角色筛选数据模型与接口设计

- 当前 `Limitless` 与角色性别控件只完成了界面交互，尚未接入真实筛选；在数据链路完成前，不将其视为已实现的业务能力。
- 后续需要为角色建立稳定、类型明确的筛选字段，至少包含角色性别与内容分级；不能依赖角色简介、徽章或其他展示文案进行判断。
- 角色性别字段的枚举值及“未指定”状态，需要结合 onboarding 中的性别选择需求统一确定。
- `Limitless` 的产品语义需要先确认：默认关闭时仅展示标准内容；开启后是展示“标准内容 + Limitless 内容”，还是只展示 Limitless 内容。
- 数据库模型、后端领域模型、Feed API 返回结构和前端角色类型需要同步更新，避免各层使用不同枚举或临时字符串。
- 正式接入真实 Feed 时，筛选应由后端查询执行，并支持类似 `gender`、`limitless` 的查询条件；不能只过滤前端当前加载的一页，否则分页结果会不准确。
- 需要补充数据库迁移、旧角色数据默认值/回填策略、接口参数校验，以及各筛选组合的后端测试。
- 当前仅记录为重要 TODO，暂不修改数据库和业务代码；在角色数据模型或 Feed API 专项设计时实施。

### 角色 Feed 与卡片

- 角色卡片常态保留：角色封面图、角色名称、一句简介、热度/互动数量。
- 已确认删除：`Editor’s Pick`、`Trending`、`New` 等卡片徽章。
- 已确认删除：创作者头像和创作者名称。
- 已确认删除：角色名称后方的声音小图标。
- 角色名称和一句简介的字号都适当放大。
- 名称与简介组成的文字信息区约占整个角色封面高度的四分之一；具体字号、行数和间距在实现时按桌面与移动端分别适配。
- 已确认卡片信息顺序：角色名称 → 热度/互动数量 → 一句简介。
- 热度位于角色名称下一行、简介上一行，使用紧凑的次级字号和样式；不与角色名称放在同一行。
- 已确认：桌面端鼠标悬停角色封面时，显示覆盖在封面上的角色详情层。
- Hover 详情层展示角色头像、详细角色简介和底部聊天 Action Bar。
- 当前聊天 Action 为醒目的 `Chat Now` 按钮，视觉方向以用户提供的参考图为准。
- Hover 时封面图继续作为背景，并增加暗色遮罩，保证简介和按钮清晰可读。
- 点击角色封面任意位置进入该角色聊天页。
- 点击 `Chat Now` 同样进入该角色聊天页；两者目标和会话创建逻辑一致。
- 已确认：触屏/移动端单击角色卡片直接进入聊天，不先展开详情层。
- Hover 详情层只在支持鼠标悬停的设备上启用，不能阻碍触屏点击。
- 已确认：角色 Feed 使用响应式多列网格，角色卡片随页面向下持续排列。
- 角色较多时采用向下滚动继续加载，不使用横向翻页，也不限制为固定两排。
- 已确认：所有角色卡片采用统一高度和统一封面比例，不使用高低不一的瀑布流。
- 封面图片按统一容器裁切；卡片文字和 Hover 操作层的位置保持一致。

### 登录、用户和金币入口

- 已确认：首页角色 Feed 对未登录用户开放，不使用登录弹层阻塞浏览。
- 已实现：公开浏览与产品可用性检查解耦；游客无需登录即可请求 Feed，但 Plum 产品总开关关闭时，未登录和已登录访问都返回产品不可用。
- 前端需要区分产品未开放、未登录和普通网络错误，不能把产品关闭显示成空 Feed。
- 未登录用户点击角色卡片或 `Chat Now` 时再触发登录。
- 登录成功后继续进入用户原本选择的角色聊天页，不要求用户返回首页重新选择。
- 已确认：未登录时不显示金币余额。
- 已确认：未登录时，账户区域显示紧凑的登录图标；点击后打开登录流程。
- 已确认：未登录用户点击 Create 时先登录，成功后自动继续进入角色创建页。
- 需要登录的操作统一保留原始目标，完成登录后继续执行，而不是返回首页中断流程。
- 已确认：顶部金币余额是可点击入口，不是纯展示文本。
- 点击金币后打开金币明细面板。
- 金币明细面板至少包含：当前余额、消费记录、充值入口。
- 待后续专项讨论：面板形态与布局、账单字段、分页、充值套餐、支付流程和异常状态。

### 空状态、加载状态和错误状态

- 已确认：加载状态采用轻量方案，不实现角色卡片骨架屏。
- 首次加载时，在首页内容区中央显示小型加载动画和本地化的 `Loading characters…` 文案。
- 向下加载更多角色时，只在列表底部显示小型加载动画。
- 内容区保留基本高度，减少加载前后的明显布局跳动。
- 已确认：筛选无结果时显示本地化的“没有找到符合条件的角色”提示和“清除筛选”按钮。
- 点击“清除筛选”只重置 `Limitless`、角色性别和标签等附加筛选，不改变当前主内容分类。
- 已确认：首次加载失败时显示简短、本地化的错误提示和“重新加载”按钮。
- 已有角色内容仍可展示时，不清空现有 Feed；在内容区顶部显示轻量错误条并提供重试。

### 页脚及其他入口

- 已确认：首页保留轻量页脚。
- 页脚在角色列表加载到末尾后出现，不阻碍向下持续加载角色。
- 页脚包含：隐私政策、服务条款、社区准则、About 和版权信息。
- 具体目标页面及其内容后续设计。

### 移动端角色网格

- 已确认：普通手机每行展示 2 张角色卡片。
- 很窄的手机仍优先保持 2 列，通过缩小间距适配。
- 平板根据可用宽度展示 3–4 列。
- 桌面端根据可用宽度自动增加列数。
- 所有断点保持统一卡片比例和高度体系。
